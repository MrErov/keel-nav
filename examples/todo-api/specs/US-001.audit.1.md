# GOLDFISH AUDIT: US-001 — Create a todo item

## Verdict

**rejected** — 2 blocking, 5 warning, 3 info.

## Blocking findings (2)

| # | Category | Location | Finding |
|---|----------|----------|---------|
| B1 | CONTRADICTION | §4 T-4 / §3.2 | T-4 expects the second POST of the same title to return the first row's id, while §3.2 requires one row per successful insert and the context doc defines `id` as autoincrement. |
| B2 | HIDDEN_ASSUMPTION | §3.1 / §3.2 / AC-3 | The spec never states whether a title with surrounding whitespace is stored and returned stripped or as received, so `"  buy milk  "` has two valid implementations and no AC or test distinguishes them. |

## Warnings (5)

| # | Category | Location | Finding |
|---|----------|----------|---------|
| W1 | GAP | §3.1 / §7 G5 | The response contract documents only 201 and omits the 422 required by AC-2, while §7 G5 is marked passed. |
| W2 | AMBIGUITY | §2 AC-3 | AC-3 omits the 201 status and refers to "the created todo" without pointing to §3.1's response shape, so it is not verifiable from §2 alone. |
| W3 | GAP | §2 AC-1 / §4 T-1, T-5 | No AC or test specifies that the persisted `title` and `created_at` values are checked, or that `created_at` is ISO 8601 UTC, so T-1's "row in DB" and T-5's presence check can pass on incorrect values. |
| W4 | GAP | §3.1 / §2 AC-2 | Behavior for a missing `title` key, a non-string `title`, or unknown payload fields such as client-supplied `created_at` is undefined, and AC-2 covers only empty and whitespace-only strings. |
| W5 | GAP | §4 → §7 | The spec jumps from §4 to §7, leaving §5 and §6 absent without an N/A marker. |

## Info (3)

| # | Category | Location | Finding |
|---|----------|----------|---------|
| I1 | HIDDEN_ASSUMPTION | §2 AC-1 / §3.2 | AC-1 names SQLite and §3.2 names a `todos` table, while the context doc declares only the `Todo` entity and no storage engine. |
| I2 | AMBIGUITY | §4 T-3, T-5 | T-3 and T-5 are labeled `unit` but describe HTTP POST and HTTP response behavior, so the test seam is ambiguous. |
| I3 | GAP | §4 T-3 | T-3 verifies only the 422 for a whitespace-only title and does not assert AC-2's "no row is inserted" for that case. |
