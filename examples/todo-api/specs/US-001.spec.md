# SPEC: US-001 — Create a todo item (v0.1.3, draft, pending real round 4)

## 1. [M] User Story

**As a** user,
**I want** to create a todo item,
**so that** I can track what I need to do.

**Bounded context:** `todos` (reference: `docs/context/todos.md`)

**Explicit out of scope:**
- Listing todos.
- Updating or deleting todos.
- Authentication or ownership.
- Any UI. The interface is the HTTP API only.
- Internal whitespace normalization (collapsing `"buy  milk"` to
  `"buy milk"`). `strip()` trims leading/trailing only; internal
  whitespace is preserved as-is.

---
## 2. [M] Acceptance Criteria

| ID | Given (context) | When (action) | Then (observable result) |
|----|-----------------|---------------|--------------------------|
| AC-1 | A client and an empty `todos` table | The client POSTs `{"title": "buy milk"}` | Response is `201` with body `{"id": <positive int>, "title": "buy milk", "created_at": <ISO 8601 UTC string>}`, and a row with `title = "buy milk"` exists in SQLite |
| AC-2 | A client and an empty `todos` table | The client POSTs `{"title": ""}` or `{"title": "   "}` | Response is `422` with body `{"error": "title_required", "detail": <non-empty string>}`, and no row is inserted |
| AC-3 | A client and an empty `todos` table | The client POSTs `{"title": "  buy milk  "}` | Response is `201`; body `title` equals `"buy milk"` (stripped); persisted row `title` equals `"buy milk"` |
| AC-4 | A client and an empty `todos` table | The client POSTs `{"title": "buy milk"}` (already clean) | Response is `201`; body `title` equals `"buy milk"` (strip is no-op); persisted row `title` equals `"buy milk"` |

---
## 3. [M] Interface Contracts

### 3.1 Input contract

```
POST /todos
Content-Type: application/json
```
Payload:
```
title: string
```
Validation: after `strip()`, title must be non-empty.
Normalization: the title is stripped (leading/trailing whitespace
removed) before validation, persistence, and response.
Internal whitespace is preserved as-is.
Responses:
```
201: {"id": <positive int>, "title": <string, stripped input>,
"created_at": <ISO8601 UTC string>}
422: {"error": "title_required", "detail": <string>}
```

### 3.2 Output contract / side effects

- One row inserted into `todos` with the title **after `strip()`** and
  `created_at` set to the current UTC time in ISO 8601.
- No row inserted on validation failure.

- **Expected (before Phase 3):**

  - Two POSTs more than 1 second apart produce distinct `created_at`

  - A `422` response contains no `id` field (no row created).
  - Response time for a valid POST is under 200ms (informational; no AC
    constrains it).
