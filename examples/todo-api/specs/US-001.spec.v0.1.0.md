# SPEC: US-001 — Create a todo item (v0.1.0, draft)

## 1. [M] User Story

**As a** user,
**I want** to create a todo item,
**so that** I can track what I need to do.

**Bounded context:** `todos` (reference: `docs/context/todos.md`)

**Explicit out of scope:**
- Listing todos.
- Updating or deleting todos.
- Authentication or ownership.
- Any UI. The interface is the HTTP API only.

---

## 2. [M] Acceptance Criteria

| ID | Given (context) | When (action) | Then (observable result) |
|----|-----------------|---------------|--------------------------|
| AC-1 | A client and an empty `todos` table | The client POSTs `{"title": "buy milk"}` | Response is `201` and a row exists in SQLite |
| AC-2 | A client and an empty `todos` table | The client POSTs `{"title": ""}` or `{"title": "   "}` | Response is `422`, and no row is inserted |
| AC-3 | A client and an empty `todos` table | The client POSTs `{"title": "buy milk"}` | Returns the created todo |

---

## 3. [M] Interface Contracts

### 3.1 Input contract

```
POST /todos
Content-Type: application/json
```

Payload:

```
title: string — non-empty after strip()
```

Responses:

```
201: {"id": int, "title": string, "created_at": string}
```

### 3.2 Output contract / side effects

- One row inserted into `todos` with the given title and `created_at`
  set to the current UTC time.
- No row inserted on validation failure.
